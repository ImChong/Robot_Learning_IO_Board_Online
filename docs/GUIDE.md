# 使用与数据编写指南

README 只讲项目重点，这里放完整的操作说明与数据文件写法。设计取舍与九个项目逐项核对过的内容基线见 [PLAN.md](../PLAN.md)。

## 页面怎么用

| 操作 | 说明 |
|---|---|
| 顶栏项目下拉 | 可搜索、按方法族分组。搜索命中项目名、副标题与关键词（机器人、仿真器、算法、机构、arXiv 号等）。快捷键 `P` 打开，`[` `]` 切上下一个 |
| 训练态 / 部署态 | 同 id 的模块做位置补间，仅训练可见的模块淡出（快捷键 `T` `D`） |
| 节点图 / 对比 / 表格 | 节点图是主视图；对比是两个项目的逐项对照；表格是同数据的无障碍与打印形态 |
| 讲解 | 按**代码运行顺序**逐个模块高亮并解说：数据源 → 取参考帧 → 本体观测 → 拼接 → 网络前向 → 动作链 → 环境步进 → 奖励与更新。可自动播放，也可自己翻步；点图上任意模块直接跳到讲它的那一步。讲过的连线才有光点在流，于是「数据已经走到这里」是看得见的。快捷键 `G` 进出，空格播放/暂停，`←` `→` 前后一步 |
| hover 模块 | 高亮它的完整上下游链路，链路上的流动光点同时加亮加快 |
| 点击模块 | 右侧详情抽屉显示维度构成、分量顺序、真机如何获得、出处链接；URL 同步，可分享 |
| 点击连线 | 点线（或线上的标注）看这条线本身：属于哪一类流、搬的是哪个向量多少维、走的是前向还是回路、部署时还在不在。图上只留它两端，其余压暗。抽屉里点「起点 / 终点」跳到那个模块的详情；反过来，模块详情的「连线」一节列出它全部的上下游连线，点一条就回到线的详情——那也是键盘唯一的入口（图本身是 `aria-hidden` 的 SVG）。URL 记成 `?e=起点>终点`，同样可分享 |
| Index 分布 | 模块与连线的详情里都有一块「Index 分布」：上面一条条形图按拼接顺序分段（宽度 ∝ 维数），下面一片方格一格一个数。点一段，下方长出它内部的下一层（帧 → 关节 → 分量），可以一直点到最细，再点一次同一段退回；点任意一格，说明卡给出这个数从外到内的完整路径（如 `index 76：关节位置（相对默认位姿） › 左髋r`）、每一层的 index 范围、原文与所属模块，`‹` `›` 逐个前后走（这也是键盘入口，方格本身 `aria-hidden`）。连线详情画的是这条线搬的向量；终点是拼接节点时再画一块「落在终点的位置」，把这一段在终点里占的 index 范围预先选中。没有维度的模块（网络、仿真环境）列出它吃进与吐出的向量，点哪个画哪个。超过 1024 维的向量方格只画选中的那一段 |
| 奖励曲线 | 奖励面板里，写了公式的奖励项右侧画一条「奖励值 ↔ 误差 / 状态量」曲线：纵轴是公式本身的值（未乘权重），横轴是公式里的那个量。每个可调参数（σ、scale、阈值、λ……）一根滑块，旁边标着数据值；拖动时实线跟着变、数据值留一条虚线作参照，「复位到数据值」一键回去。横轴范围按数据值定死、不随滑块缩放，于是 σ 调大一倍，钟形就真的宽了一倍。悬停（触屏点按）有十字线读数。多元公式只画一维，其余量用标着「固定」的滑块定住；参考线标出 σ、1/√s、阈值等位置。只取 0 / 1 或常数的项写明为什么没有曲线 |
| 只看…筛选 | 按观测类别、部署可得性、可信度过滤。未匹配的模块与连线压暗，可多选，点「清除」恢复全图 |
| 对比 | 当前项目 vs 一个选定的对比对象，逐项对照 |
| 图例 | 展开全部视觉编码的含义。连线十一类只列名字，每一类是什么意思写在 `data/taxonomy.json` 的 `edgeKinds[].desc` 里，点图上任意一条线就能看到 |
| 画布 | 滚轮缩放、拖拽平移，`适应窗口` 或 `F` 复位。触屏上单指平移、双指捏合缩放，画布右下角还有一组缩放按钮 |
| 连线流动 | 连线上有光点顺着数据流向走：每条边往哪个方向流不必去认箭头，回路边绕到上下通道之后拐去了哪也跟着看得见。光点按起点所在的列错开相位，于是整张图是一波数据从输入侧推到输出侧。工具栏 `流动` 或快捷键 `L` 开关，选择记在 `localStorage`；系统开了「减少动态」时默认关着 |
| 手机 | 顶栏在任何手机尺寸下都只占一行（含横屏），窄屏时 GitHub 入口收成图标按钮、留在顶栏里，不必滑到页脚才找得到源码。详情与讲解都从底部升起，同时把画布顶到顶栏底下，读者始终看得见自己点的是图上的哪一格；横屏时讲解改贴右侧，因为那种视口缺的是高度不是宽度。`适应窗口` 在窄屏保留可读比例而不是把整张图压到看不清——想看全景就捏合缩小 |
| 主题 | 顶栏右上角切换深浅色，选择记在 `localStorage`。色板、站点顶栏与页脚沿用 [imchong.github.io](https://github.com/ImChong/ImChong.github.io) 与 [Robot_Joint_Order_Check_Tool](https://github.com/ImChong/Robot_Joint_Order_Check_Tool)：Notion 风暖中性色 + 同一支蓝作强调色 |

## 加一个项目

1. 在 `data/` 下新建 `<项目>.json`，结构见 `schema/project.schema.json`；
2. 在 `data/projects.json` 的 `projects` 里登记一行：

```json
{
  "id": "my-project",
  "file": "my-project.json",
  "name": "MyProject",
  "subtitle": "一句话定位",
  "group": "wbt",
  "published": "2026-01-15",
  "venue": "arXiv 预印本",
  "keywords": ["Unitree G1", "Isaac Lab", "AMP", "某某大学", "2601.01234"]
}
```

3. 跑 `node scripts/validate.mjs`。

`published` 是**首次公开发表的日期**（有预印本就以预印本首版为准，否则取会议/期刊日期），项目列表按「分组顺序 → 发布时间从早到晚」排。所以加项目不用管别人的序号，填对日期它就会落到自己在这条技术线上的位置；日期显示在下拉列表右侧与项目头，读者能核对这个顺序。`venue` 只用于展示。

页面本身不含任何项目专属逻辑，所有分类、配色与文案都来自数据文件。讲解也一样：顺序由 `src/tour.js` 从图的泳道与连线推出来，解说词直接取自节点已核对过的 `desc` / `note` / `source`，新项目不必再手写一份步骤表。校验脚本会确认推出来的序列覆盖每个模块且只讲一次。

关于规模：项目文件是**按需加载**的，首屏只下载 `taxonomy.json` + `projects.json` + 当前项目，所以项目数量不影响加载速度。注册表里冗余了 `name` / `subtitle` 就是为了让选择器不必先下载每个项目文件，校验脚本会保证这两处与项目文件一致。

`keywords` 只参与搜索、不显示，放读者可能拿来搜的词（机器人型号、仿真器、算法、机构、代码仓名、arXiv 号，中英文都行）。发布日期与 `venue` 也参与搜索，所以按年份搜（如 `2021`）能筛出那一年的方法。

`file` 是相对 `data/` 的路径，所以可以放进子目录（`"file": "mimickit/amp.json"`）。新增一个方法族时，在 `groups` 里加一条，然后让项目的 `group` 指向它——选择器会自动按组显示标题。

### 消融式项目：只写差异

如果新项目与已有项目共用同一份环境配置、只换了算法（MimicKit 里 LCP 对 DeepMimic 就是这样：`--env_config` 指的是同一份 `deepmimic_g1_env.yaml`，agent 只多一行 `lcp_weight`），可以只写差异：

```json
{
  "id": "my-ablation",
  "name": "MyAblation",
  "inherits": "my-project",
  "diffSummary": "必填，一句话说明差在哪，直接渲染在页面顶部",
  "overrides": {
    "modes.train": {
      "facts": { "Actor 更新规则": "换掉的值" },
      "nodes": { "l.ppo": { "label": "新标签", "desc": "……" } },
      "nodes+": [],
      "nodes-": []
    }
  }
}
```

被补丁命中的模块会在图上带一个「改动」角标，所以「只有这一个框变了」是看得见的。合并逻辑在 `src/inherit.js`，页面与校验脚本共用同一份，校验会检查补丁目标在父项目里真实存在（写错 id 不会静默失效）。**继承只允许一层**，而且只在环境配置真的相同时才划算——换机器人就别用它，维度全都不一样。AWR 就是这么被踢出继承的：DeepMimic 的页面改用随仓库分发的 G1 配置之后，AWR 只有 humanoid 一份配置，每个维度都对不上，于是改写全量数据文件。

### 奖励曲线怎么来的

不另写数据：`src/reward-curve.js` 认 `form` 的 TeX 写法，常数取自 `params`（键名如 `σ`、`scale`、`threshold`、`阈值`、`*_scale`），`params` 里没有的就用公式里写死的那个数。认不出的写法不画（校验脚本给提示），绝不按名字猜一个函数。新项目想有曲线，就把公式写成已有的几类写法之一，常数放进 `params`；真是新写法，就在 `FAMILIES` 里加一类。为了画成一维做的取舍（横轴取均方误差的平方根、多元公式固定其余量为 0、无参数项的横轴范围只是示意）都会写在曲线下方。

### 学习式奖励

判别器、编码器、扩散先验这类奖励没有可以逐条列出的分项权重，写法不同：`rewardKind` 填 `adversarial` / `encoder` / `generative`，`weight` 填配置里真实存在的混合系数，真正的信息放进 `model`（吃什么、正负样本怎么定、网络多大、有哪些正则、参数是否冻结）。奖励面板会把这类项渲染成「来源卡」而不是权重条。`model.inputs` 要指向同一张图里存在的节点 id，校验脚本会检查。

## 数据准确性

内容以**开源实现**为准，而不是论文或二手资料的口径：

- 每个维度与权重都带 `source`，指向仓库文件路径与配置项名，在详情抽屉里可点开；
- 总维度只能标 `derived`，由逐项核对过的维度求和得出，`scripts/validate.mjs` 会对维度算式求值、并按入边求和验证聚合节点，防止手算漏项；
- **维度只写大小不算数**：每个带维度的观测与动作节点都要写 `dimLayout`，说明这几个数按什么顺序排，校验脚本会强制要求（其余节点缺了只是提示）。四元数写「4 维」等于没写——同一台 Unitree G1，MimicKit 跑在 Isaac Gym 上是 `(x, y, z, w)`，BeyondMimic 与 SONIC 跑在 Isaac Lab 上是 `(w, x, y, z)`；关节顺序也有三套（Isaac Lab 广度优先、MJCF 深度优先、真机 SDK 顺序），维度对得上而顺序错了，是不会报错的那类 bug；
- **每个 index 是什么由数据推出来，不另写一份表**：拼接节点按入边顺序分段（校验脚本拿 `dimExpr` 的分项核对入边顺序，入边写乱了直接报错），段内按各模块自己的 `dimLayout` 展开——`(x, y, z)`、`帧 t−9 → t × …`、`14 连杆按 body_names 序（…） × …`、`[A | B]`、`拼接顺序：a 3 · b 6 · …` 这几种写法都认得。原文只写了排序规则没列名字的（如「关节 1…29 按 Isaac Lab 广度优先序（左髋p · … · …）」只列了前 6 个），页面只给序号并明说，不补名字；解析出来的各段加起来对不上 `dim` 时校验失败。所以想让读者点到某个数时看到具体名字，就把名字写进 `dimLayout`；
- 论文口径与实现口径不一致时，图以实现为主体，差异写在模块的备注里；
- 每个项目记录 `verifiedAt` 与 `verifiedRef`（分支与所选配置），上游仍在迭代。
